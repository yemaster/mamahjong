# 房间规则与客户端布局计划

状态：设计完成，待实现  
最后更新：2026-07-31

## 目标

- 房间创建支持当前日麻模型的全部规则字段，不再提供残缺表单。
- 普通规则、A 规则、最高位规则、M League（ML）规则可直接选择。
- 预设是配置基线；房主可以在预设上修改任意允许覆盖的字段。
- TUI 在紧凑、常规和宽屏终端下保持一致的边距、分栏和信息层级。
- 管理端登录页使用纯色响应式布局，不使用图片、渐变或自定义样式表。
- 客户端继续独立于服务端和规则 crate，只依赖版本化 HTTP JSON。

## 已有能力与缺口

服务端已经实现完整 `RiichiRules`、严格校验、版本化预设和不可变规则快照。
当前 TUI 建房请求只提交以下字段：

- 人数；
- 初始点数；
- 击飞；
- 流局罚点；
- 头跳。

因此缺少预设、马点、途中流局、流局满贯、切上满贯、役满规则、宝牌规则等
配置入口。房间内的规则摘要也只显示四项，不能核对实际生效规则。

协议文档已经保留 `GET /api/v1/rule-sets`，但服务端尚未实现。客户端不能自行
复制预设常量，否则预设修订后会与服务端不一致。

## 规则目录协议

先实现只读规则目录，再实现表单。目录是所有后续 Web、桌面和移动客户端的
共同配置来源。

### 目录

```text
GET /api/v1/rule-sets
```

响应：

```json
{
  "schema": "rule_set_catalog.v1",
  "rule_sets": [
    {
      "id": "riichi/yonma",
      "display_name": "四人日麻",
      "seat_count": 4,
      "default_config": {},
      "presets": [
        {
          "id": "jpml-a",
          "revision": 1,
          "display_name": "日本职业麻将联盟 A 规则",
          "config": {}
        }
      ]
    }
  ]
}
```

约束：

- `default_config` 和 `preset.config` 都是服务端解析、校验后的完整配置；
- 预设必须返回明确修订号；
- 四麻返回 `jpml-a@1`、`saikouisen@1`、`m-league@1`；
- 三麻首版只返回普通规则，不显示不兼容的四麻竞赛预设；
- 目录响应可以缓存，但房间创建仍由服务端重新解析和校验；
- DTO 在传输层显式组装，不直接暴露领域对象。

### 房间输入

沿用现有结构：

```json
{
  "rule_set_id": "riichi/yonma",
  "config": {
    "preset": {"id": "m-league", "revision": 1},
    "overrides": {}
  }
}
```

客户端保存两份状态：

- `base_config`：当前人数和预设对应的完整配置；
- `edited_config`：房主当前编辑结果。

提交时比较两份配置，只生成发生变化的 `overrides`。切换人数或预设会载入新的
基线并清空旧覆盖项，避免把四麻字段带入三麻。

## 完整房间表单

### 分组

表单分为五页，顶部固定显示页签；页签切换不丢失输入。

| 页签 | 字段 |
|---|---|
| 房间 | 房间名、公开/私有、四麻/三麻、规则预设 |
| 对局 | 东风/东南、初始点数、返点、击飞、连庄条件、和了止 |
| 和牌 | 切上满贯、古役、役满算法、流局满贯、累计役满、国士抢暗杠 |
| 宝牌与流局 | 赤五万/筒/索、一发、里宝、杠宝、四风连打、四杠散了、九种九牌、四家立直 |
| 结算 | 马点类型、马点值、流局罚点、荣和方式 |

字段显示名称：

| 协议字段 | 界面名称 | 可选值或格式 |
|---|---|---|
| `length` | 对局长度 | 东风战 / 东南战 |
| `initial_points` | 初始点数 | 千点整数，默认 25000 |
| `return_points` | 返点 | 千点整数，默认 30000 |
| `tobi` | 击飞 | 有 / 无 |
| `dealer_continuation` | 连庄 | 和牌或听牌 / 仅和牌 |
| `agari_yame` | 和了止 | 有 / 无 |
| `kiriage_mangan` | 切上满贯 | 有 / 无 |
| `old_yaku` | 古役 | 有 / 无 |
| `yakuman_value` | 特殊役满 | 双倍并叠加 / 仅叠加 |
| `nagashi_mangan` | 流局满贯 | 有 / 无 |
| `kazoe_yakuman` | 累计役满 | 有 / 无 |
| `kokushi_ankan_chankan` | 国士抢暗杠 | 有 / 无 |
| `red_fives.man` | 赤五万 | 0..4；三麻固定为 0 |
| `red_fives.pin` | 赤五筒 | 0..4 |
| `red_fives.sou` | 赤五索 | 0..4 |
| `ippatsu` | 一发 | 有 / 无 |
| `ura_dora` | 里宝 | 有 / 无 |
| `kan_dora` | 杠宝 | 有 / 无 |
| `four_winds` | 四风连打 | 有 / 无；三麻不可用 |
| `four_kans` | 四杠散了 | 有 / 无 |
| `nine_terminals` | 九种九牌 | 有 / 无 |
| `four_riichi` | 四家立直 | 有 / 无；三麻不可用 |
| `uma` | 马点 | 固定数组或 A 规则浮动马点 |
| `noten_payment` | 流局罚点 | 整数，默认 3000 |
| `ron_resolution` | 荣和方式 | 头跳 / 多家和 |

“途中流局”在页签标题旁显示汇总状态：

- 全部开启；
- 全部关闭；
- 自定义。

它是四个途中流局字段的计算结果，不增加新的协议字段。三麻不可能成立的
四风连打和四家立直显示“不可用”，不能获得焦点。

### 预设

预设选择顺序：

```text
普通规则 → A 规则 → 最高位规则 → M League（ML）规则
```

规则：

- 三个竞赛预设只在四麻显示；
- 切换预设立即用目录中的完整配置刷新所有页签；
- 修改任意字段后，预设显示为“预设名 · 已修改”；
- 选择“普通规则”后，以目标人数的 `default_config` 为基线；
- 房间详情显示来源预设和实际配置，不用预设名代替规则摘要。

### 输入与校验

- `↑/↓` 选择字段；
- `Tab/Shift+Tab` 顺序移动；
- `[`、`]` 切换页签；
- `←/→` 或 `Space` 修改布尔和枚举；
- 数值和文本字段直接输入，`Backspace` 删除；
- `Ctrl+S` 创建房间；
- `Esc` 返回大厅。

提交前检查数字格式、马点人数和马点合计。服务端仍执行最终校验；错误响应保留
字段路径，TUI 自动切换到首个错误所在页签并高亮字段。

固定马点输入格式：

```text
+30,+10,-10,-30
```

四麻必须四项，三麻必须三项，合计必须为 0。A 规则预设默认显示“联盟 A 浮动
马点”；切换为固定马点后再编辑数组。

## TUI 布局

### 间距尺度

所有页面共用一组终端单元尺度，不在各渲染函数中散落百分比和空行：

| 名称 | 紧凑 | 常规/宽屏 |
|---|---:|---:|
| 页面水平边距 | 1 | 2 |
| 页面垂直边距 | 0 | 1 |
| 面板间距 | 1 | 2 |
| 面板水平内边距 | 1 | 2 |
| 面板垂直内边距 | 0 | 1 |
| 顶栏高度 | 2 | 3 |
| 底栏高度 | 3 | 3 |
| 表单字段间距 | 0 | 1 |

断点：

| 模式 | 终端尺寸 | 行为 |
|---|---|---|
| 紧凑 | `76..99` 宽或 `22..27` 高 | 单栏优先、1 单元间距、可滚动 |
| 常规 | `100..127` 宽且至少 28 高 | 双栏、2 单元面板间距 |
| 宽屏 | 至少 128 宽且至少 32 高 | 双栏并扩大主区域，不拉伸文本列 |

小于 `76×22` 保留明确的尺寸提示。

### 页面骨架

```text
┌ 顶栏：品牌 / 当前页面 / 用户 ┐
│                              │
│  主内容，四周留白             │
│                              │
├ 状态                         ┤
└ 当前页面快捷键                ┘
```

顶栏不再压缩为一行色块。状态与快捷键分行，左右各保留一个单元；过长快捷键
按当前宽度截断，不覆盖状态。

### 大厅

- 常规和宽屏：房间列表与“快速开始”之间插入 2 单元空列；
- 紧凑：上下分区，快速开始固定 7 行；
- 房间列表行使用固定列宽：名称、人数、玩法、状态；
- 选中行只高亮内容区，不填满边框。

### 创建房间

常规和宽屏：

```text
┌ 房间 对局 和牌 宝牌与流局 结算 ┐  ┌ 当前配置 ┐
│ 当前页字段，可滚动              │  │ 预设来源 │
│                                │  │ 核心摘要 │
└───────────────────────────────┘  └──────────┘
```

- 左侧最小 64 列，右侧 30 列，中间 2 列空白；
- 当前字段上下各保留一行，活动字段使用前景色和左侧标记，不用整行高亮；
- 页签栏、字段区、提交提示各自独立，不用手工插入大量空字符串；
- 紧凑模式隐藏右侧摘要，字段区占满宽度；
- 字段列表维护滚动偏移，活动字段始终可见。

### 房间

- 常规和宽屏：成员与规则摘要为 `3:2`，中间 2 单元空列；
- 紧凑：成员在上、规则摘要在下；
- 规则摘要按“对局、和牌、宝牌、流局、结算”分组显示；
- 首屏显示预设、人数、点数、马点、击飞、头跳；其余规则可滚动查看。

### 牌桌

- 保留四方桌面，但所有外层区域使用统一页面边距；
- 玩家区、中央场况和自家手牌之间至少保留 1 行或 2 列；
- 牌河宽度按终端断点计算，不再依赖固定百分比挤压；
- 自家手牌、动作候选和底部快捷键不得共享同一行；
- 三麻缺失座位保留桌面平衡，不把剩余玩家拉伸到整块区域。

### 渲染测试

使用 Ratatui `TestBackend` 固定验证：

- `76×22` 紧凑大厅、建房、房间、四麻和三麻牌桌；
- `100×30` 常规布局；
- `144×42` 宽屏布局；
- 面板之间存在约定空列或空行；
- 边框不重叠，底栏不覆盖内容；
- 建房字段滚动后活动项可见；
- 中文、全角牌面和长昵称不会破坏边界。

## 管理端登录布局

删除 `LoginFormPage` 默认视觉，改用 Ant Design `Layout + Row + Col + Card + Form`。

桌面：

- 纯色浅灰页面背景；
- 顶部 72px 品牌栏；
- 内容最大宽度 1440px，水平留白 48px/64px；
- 左侧 10/24 列，只显示“麻麻的将 / 管理后台”；
- 右侧 7/24 列，白色登录卡；
- 卡片内边距 40px，字段间距 24px。

移动端：

- 小于 `lg` 隐藏左侧文字区；
- 登录卡占 `xs=24, sm=20, md=14`；
- 页面水平留白 24px，卡片内边距 24px；
- 保持完整视口垂直居中。

页面不使用图片、渐变、宣传语和自定义样式表。颜色和间距从 Ant Design
主题令牌取得。

## 实施顺序

1. 服务端增加规则目录 DTO、路由和协议测试。
2. TUI 增加独立规则目录 DTO、规则草稿、预设基线和差异生成。
3. 将建房 API 从参数列表改为单一 `CreateRoomRequest`。
4. 实现五页完整建房表单、滚动、输入和字段错误定位。
5. 扩充房间规则摘要。
6. 提取 TUI 间距令牌和响应式断点，逐页替换现有布局。
7. 重写管理端登录布局。
8. 更新 README、通信协议、客户端文档和部署截图说明。

## 验收

- 四麻普通规则可以逐项配置全部 25 个现有可配置规则字段。
- 三麻隐藏竞赛预设，并禁止赤五万、四风连打、四家立直。
- A、最高位、ML 预设载入值与服务端快照测试完全一致。
- 预设上修改一个字段时，请求只包含该字段覆盖项。
- 马点支持四麻和三麻固定数组，流局罚点默认 3000。
- 途中流局四项、流局满贯、累计役满、双倍役满、宝牌规则均能在房间快照中
  核对。
- 修改房间规则后全部成员准备状态清除。
- TUI 三种断点的渲染测试通过，无边框贴合、内容覆盖和不协调空白。
- 管理登录页无图片、无渐变，在桌面和移动宽度下布局正确。
- 前端类型检查、测试和生产构建通过。
- Rust 格式化、Clippy、全工作区测试通过。
- Docker 重建后执行真实注册、建房、预设、自定义规则和开局流程。

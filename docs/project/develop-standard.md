# 开发规范

## 代码修改流程

1. 先写设计文档，明确要解决的问题、方案和影响范围。
2. 设计时参考已有成熟案例，不在无调研的情况下自行发明方案。
3. 按设计文档逐步实现，代码结构清晰，格式规范。
4. 破坏性协议或存储变更必须先提交 ADR。

## 文档要求

- 技术描述准确、简洁，不添加无信息量的背景铺垫和同义反复。
- 文档结构按主题分层，不使用过长段落堆砌信息。
- 交叉引用使用相对路径，目标文件移动后同步更新链接。
- 每个里程碑结束时更新相关设计文档。

## 界面要求

- 布局合理，信息层级清晰。
- 不使用渐变色，层次通过纯色和透明度表达。
- 组件状态（加载、空、错误）必须覆盖。

## 提交要求

- 每个可勾选项一个提交，不混入下一阶段功能。
- 提交前通过格式化、Clippy、全工作区测试与前端类型检查。
- 为核心不变量增加测试。

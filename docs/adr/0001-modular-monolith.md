# ADR-0001：模块化单体优先

状态：采纳  
日期：2026-07-29

## 背景

项目需要低延迟桌局、房间、匹配和持久化，但早期团队与负载未知。直接拆分
微服务会让事务、协议演进和本地测试复杂化。

## 决定

首期使用一个可部署后端进程，内部按 Identity、Lobby、Matchmaking、Game
和 Ranking 分模块。每桌采用单写任务顺序处理命令。模块只通过应用接口和
事件交互，不跨模块直接修改存储。

## 后果

- 可以在一个事务中保证开局、事件、结果和 outbox 一致；
- 本地开发和端到端测试简单；
- 热点桌局可以并发运行；
- 将来按负载拆服务时，现有模块接口和 outbox 是明确切割线。

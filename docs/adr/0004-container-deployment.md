# ADR-0004：OCI 容器作为标准部署单元

状态：采纳  
日期：2026-07-29

## 背景

项目需要在开发机和服务器上以一致方式构建、启动和停止。直接依赖宿主机
Rust 工具链容易产生版本漂移，也不利于后续加入数据库和反向代理。

## 决定

使用多阶段 Dockerfile 构建 release 二进制，以无 shell 的 Distroless
Debian 镜像作为标准部署单元。镜像内附带一个无外部依赖的只读健康检查
程序。Docker Compose 提供单机一键部署，默认只映射到宿主机回环地址。
构建阶段使用 BuildKit 缓存保存 Cargo registry 和编译产物，源码变化不要求
重复编译全部第三方依赖。

运行容器必须：

- 以 digest 固定构建和运行基础镜像；
- 使用固定非 root UID/GID；
- 只读根文件系统并移除 Linux capabilities；
- 提供容器级 readiness 健康检查；
- 使用 SIGTERM 和服务端优雅停机；
- 限制日志文件大小和进程数量；
- 不把 `.env`、Git 元数据或本机构建产物放入镜像。

## 后果

- 本地与生产使用相同的服务二进制和启动方式；
- 镜像构建时间高于直接运行本地二进制；
- Docker Compose 只负责单机编排，未来多节点部署需要独立编排清单；
- 数据库加入后必须使用命名卷或外部托管服务，不能写入容器根文件系统。

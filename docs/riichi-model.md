# 日麻基础模型

状态：M1 设计基线  
最后更新：2026-07-30

## 模块边界

日麻实现位于独立 crate `mahjong-riichi`。`mahjong-core` 只保留跨玩法的 ID、
版本和规则接口。四麻与三麻共享日麻类型和算法，通过经过校验的
`RiichiVariant` 与配置表达差异。

川麻、武汉麻将等玩法不得依赖 `mahjong-riichi`，也不向日麻类型增加对应
分支。

## 牌对象

```text
TileKind       逻辑牌种，紧凑索引 0..33
Tile           一张物理牌：局内 ID + TileKind + 赤牌标记
TileSet        一副尚未洗牌的不可变物理牌集合
Wall           洗牌后带摸牌游标和王牌分区的状态
```

`TileKind` 的 34 种顺序是日麻引擎内部性能约定：

```text
0..8    1m..9m
9..17   1p..9p
18..26  1s..9s
27..33  东南西北白发中
```

该索引用于数组计数、向听和役判定，不是公开 API 或长期存储编码。外部协议
使用字符串牌码；快照必须记录自身 schema 和引擎版本。

牌码采用：

- `1m` 到 `9m`：万子；
- `1p` 到 `9p`：筒子；
- `1s` 到 `9s`：索子；
- `1z` 到 `7z`：东、南、西、北、白、发、中；
- `0m`、`0p`、`0s`：对应花色的赤五。

赤牌是物理牌属性，不是第 35 种牌。赤五与普通五在牌型计算中具有相同
`TileKind`。

`TileId` 只在一局内部唯一，不跨局复用为业务实体。内部数值 ID 不直接发送
给客户端；通信层以后生成不可推断牌种或牌山位置的不透明句柄。

## 牌集合

### 四人

- 34 种牌各 4 张，共 136 张；
- 每种牌数量始终为 4；
- 赤五配置分别替换万、筒、索的普通五，每门范围 `0..=4`；
- 默认 `1m + 1p + 1s`，即三赤。

### 三人

- 移除二万到八万，共移除 28 张；
- 一万、九万及其他牌仍各 4 张，共 108 张；
- 万子五不存在，因此万子赤五必须为 0；
- 初始默认 `1p + 1s`。

牌集合构建必须一次完成校验；无效赤牌配置不能产生部分集合。

## 洗牌与随机性

每局使用独立的 256 位 `WallSeed`：

1. 生产种子由操作系统 CSPRNG 生成；
2. 使用 ChaCha20 确定性随机流；
3. 使用无模偏差的 Fisher–Yates 原地洗牌；
4. 同一引擎版本、牌集合与 seed 必须得到相同顺序；
5. 洗牌后的完整顺序进入加密快照，seed 进入加密 secret payload。

测试可以注入固定 seed。禁止使用时间戳、弱 PRNG 或全局共享 RNG 创建生产
牌山。

随机算法和依赖版本属于 `engine_version` 的确定性行为。算法变化必须提升
引擎版本，不能改变进行中或历史牌局的重放结果。

## 牌山分区

日麻牌山固定保留 14 张王牌：

```text
Wall
├── live wall       普通摸牌区
└── dead wall (14)
    ├── rinshan     4 张岭上牌
    ├── dora        5 张宝牌指示牌
    └── ura-dora    5 张里宝指示牌
```

初始公开一个宝牌指示牌。每次成功杠：

- 最多消耗一张岭上牌；
- 普通可摸牌上限减少一张，保持王牌逻辑数量；
- 是否以及何时翻开新杠宝由 M2/M3 规则控制，牌山只提供受限操作。

牌山不直接决定杠是否合法，也不决定玩家能否查看里宝。

## 对局进度

日麻进度对象包含：

- 玩法人数；
- 场风；
- 局号；
- 庄家座位；
- 本场数；
- 供托立直棒数。

座位使用从 0 开始的稳定索引，风位根据当前庄家计算。三麻只有三个有效
座位，但场风和值牌仍可使用完整的东南西北枚举。

本场和供托使用非负整数与 checked 运算，禁止溢出和负数状态。点数转移在
M4 计分模型中实现。

## M1 验收不变量

- 34 种 `TileKind` 的索引唯一且可以无损转换；
- 非五牌不能标记为赤牌；
- 四麻固定 136 张、三麻固定 108 张；
- 每个保留牌种恰好 4 张，所有 `TileId` 唯一；
- 三麻不存在二万至八万；
- 固定 seed 的牌山顺序稳定，不同 seed 产生不同顺序；
- 普通摸牌、岭上牌和指示牌分区不重叠；
- 杠后普通可摸数量正确减少；
- 座位、局号、本场和供托的非法状态无法构造。

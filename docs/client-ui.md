# 客户端与 UI 演进

状态：终端可玩版已实现
最后更新：2026-07-31

## 路线

首个客户端是终端 TUI，不是逐行输入的临时脚本。后续网页端和原生应用复用
协议、观察者视图、交互状态机和视觉令牌，但各自使用适合平台的渲染层。

```text
WebSocket / HTTP DTO
        ↓
Client session + command state
        ↓
Observer ViewModel
        ├── Terminal TUI
        ├── Test Bot
        ├── Web UI
        └── Native app UI
```

客户端从不重算合法动作、和牌或分数；只展示服务端给当前观察者的裁剪视图，
并提交带预期版本的意图。WebSocket 阶段再加入命令 ID 和幂等回执。

当前 `clients/console` 不依赖服务端、应用层或日麻 crate，只维护自己的 HTTP
DTO。服务端与客户端可以使用不同语言。详细约束见
[ADR-0008](adr/0008-protocol-separated-clients.md)。

## 终端 TUI

当前界面包含：

- 房间列表、建房规则表单、成员与准备状态；
- 四麻/三麻自适应桌面；
- 四方位座位、昵称、点数、风位和立直状态；
- 自家手牌、各家牌河、副露、宝牌指示牌、场况与剩余牌数；
- 摸切区分和当前可选动作；
- 键盘选择牌、确认、取消、吃碰杠、立直、和牌与过；
- 自动状态同步和错误提示。

当前已实现登录、注册、房间列表、建房、加入、准备、四麻/三麻桌面、打牌、
立直、自摸、荣和、过、吃、碰、明杠、暗杠、加杠和九种九牌。弃牌后，无
合法响应时立即推进；有合法响应时只向对应玩家显示可选动作。状态同步暂用
500ms HTTP 轮询；操作倒计时、超时自动过和断线续传随 WebSocket 阶段实现。

界面固定为顶部场景栏、主内容和底部操作栏。底部只列当前场景可用的按键；
牌桌不重复显示帮助文字。大厅把公开房间和四麻/三麻快速匹配分区。牌面显示
为 `1萬 / 1筒 / 1索 / 東南西北白發中`，赤牌使用红色，当前牌、摸牌和标记
牌另有符号。终端小于 `76×22` 时直接提示调整窗口。

吃、碰、明杠只有一种合法组合时直接提交；存在多种组合时才要求标记手牌。
操作栏使用 `c 吃 / p 碰 / k 杠 / h 荣和 / s 过`。这套约定参考了
[MahjongCLI](https://github.com/YarrowRen/MahjongCLI) 的本地化牌面、动作提示
和输入层拆分，以及 [Ratatui application patterns](https://ratatui.rs/concepts/application-patterns/)
的状态更新与独立渲染结构；未复制素材或界面。

## 网页与应用

服务端观察者视图不包含终端坐标或 CSS。公共客户端模型使用：

- 逻辑座位与相对方位；
- 有序手牌、牌河行列、副露和动作候选；
- 语义状态，如 `riichi / disconnected / current_turn`；
- 与具体素材无关的牌面 ID。

网页和应用再把这些语义映射到响应式布局、动画、音效和触控手势。视觉目标
是尽量还原线下麻将的桌面比例、牌墙、牌河和操作节奏，同时保持清晰的在线
状态反馈。不会复制现有平台的商标、专有素材或逐像素界面。

## 视觉资源

牌面、桌布、角色和特效使用独立资源包与清单版本。逻辑代码只引用资源 ID；
默认资源必须具备明确授权。主题令牌至少覆盖桌布色、牌背、字体、间距、
动画时长和音效开关，以便网页、桌面和移动端保持一致风格。

# 开发路线

状态：执行中  
最后更新：2026-07-29

## M0 基础框架

- [x] 初始化 Git 和 Rust workspace
- [x] 确定分层、依赖方向和规则扩展边界
- [x] 设计对象模型、存储格式和通信协议
- [x] 建立核心标识符、聚合版本、规则元数据和规则定义接口
- [ ] 建立可启动的后端进程骨架

验收：workspace 的格式化、测试和静态检查全部通过。

## M1 日麻基础模型

- 牌、牌种、赤牌和牌集合
- 四人/三人牌山生成
- 座位、局、场风、本场、供托
- 可注入且可复现的洗牌

验收：牌张数量、唯一性约束和三麻移除牌规则均有测试。

## M2 规则配置

- 用户要求的全部布尔/枚举/数值规则
- 配置组合校验和清晰错误
- A、最高位、ML 等版本化预设
- 房间规则快照

验收：非法组合不能创建房间；预设有快照测试。

## M3 单局状态机

- 发牌、摸牌、打牌
- 吃、碰、杠、荣和、自摸、过
- 优先级、振听、立直和抢杠
- 途中流局与荒牌流局

验收：所有状态转换由合法动作驱动，非法或过期动作无副作用。

## M4 和牌与计分

- 面子拆分、听牌和役判定
- 符、番、宝牌、役满
- 多家和牌、包牌、流局满贯
- 连庄、终局和马点

验收：使用公开规则样例与边界牌型建立回归测试集。

## M5 房间后端

- 用户会话、建房、配置、加入、准备、观战
- WebSocket 命令/事件协议
- 桌局串行执行、超时、断线重连
- 内存仓储和集成测试

## M6 控制台客户端

- 登录和连接
- 房间创建/加入
- 手牌与牌河显示
- 合法动作交互与重连

## M7 匹配与持久化

- 段位队列和匹配策略
- PostgreSQL 战绩/规则快照
- Redis 会话/节点协调
- 可观测性、压测和部署

## 暂缓

图形客户端、付费系统、复杂社交系统及其他麻将玩法在日麻闭环稳定后进入
独立里程碑。

## 实施纪律

- 先更新设计，再实现对应模块。
- 每个勾选项使用独立提交；不在同一提交混入下一阶段功能。
- 公开协议或存储格式发生破坏性修改时，必须先增加 ADR 和迁移方案。
- 路线图中的后续项允许细化，不允许绕过当前里程碑的不变量测试。

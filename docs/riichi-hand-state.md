# 日麻单局状态机

状态：M3 已实现
最后更新：2026-07-30

## 边界

`RiichiHand` 是一局牌唯一的权威聚合。它持有牌山、各家手牌和副露、牌河、
立直与振听状态、当前动作阶段及响应窗口。外部只能提交“座位 + 命令”，不能
直接修改状态。

状态机负责：

- 配牌、摸打、吃碰杠和回合推进；
- 并发响应收集和确定性优先级；
- 立直成立时机、一发中断、同巡及立直振听；
- 九种九牌、四风连打、四杠散了、四家立直和荒牌流局；
- 产出不可变领域事件和可恢复快照。

M4 负责和牌形、役、符、番、听牌及立直后暗杠是否改变面子构成。M3 通过
只读 `HandJudge` 接口询问这些结论，不在状态机内复制计分算法。

## 聚合结构

```text
RiichiHand
├── rules                 完整 RiichiRules
├── progress              场风、局号、庄家、本场、供托
├── wall                  普通牌山、岭上牌、宝牌指示牌
├── players[3|4]
│   ├── concealed         未公开物理牌
│   ├── melds             顺子、刻子、明杠、暗杠、加杠
│   ├── discards          有序牌河及被鸣走标记
│   ├── riichi            未立直/待成立/已成立
│   ├── furiten            同巡振听、立直振听
│   └── ippatsu_eligible
├── phase
├── calls_occurred        首巡途中流局与一发中断依据
└── kan_counts
```

物理牌始终以 `TileId` 唯一定位。命令携带牌 ID，状态机再核对牌种；客户端
不能只用牌种请求“随便打一张五筒”。

### 阶段

```text
AwaitingTurnAction
    摸牌后可自摸、暗杠、加杠、九种九牌或打牌

AwaitingDiscard
    吃碰后只能从手牌打出一张，且执行食替限制

AwaitingResponses
    对弃牌或抢杠机会收集荣和、碰、吃、明杠、过

Ended
    和牌、途中流局或荒牌流局；拒绝后续命令
```

阶段是互斥枚举，不使用多个布尔值拼接非法组合。

## 开局与推进

1. 从庄家开始按座位顺序发牌，共 13 轮；
2. 庄家从普通牌山取得第一张摸牌；
3. 庄家进入 `AwaitingTurnAction`；
4. 无人鸣牌时，弃牌响应完成后由下一家自动摸牌；
5. 吃碰后调用者直接进入 `AwaitingDiscard`；
6. 杠成立后按配置翻杠宝，再取得岭上牌；
7. 普通牌山无法继续摸牌时，最后一张弃牌只开放荣和，响应完成后荒牌流局。

发牌顺序和自动推进属于引擎确定性行为，修改时必须提升
`engine_version`。

## 命令

```text
Discard { tile_id, declare_riichi }
DeclareTsumo
DeclareConcealedKan { tile_ids[4] }
DeclareAddedKan { meld_id, tile_id }
DeclareNineTerminals
Respond {
    Pass
    Ron
    Pon { hand_tile_ids[2] }
    Chi { hand_tile_ids[2] }
    OpenKan { hand_tile_ids[3] }
}
```

动作发送者由会话取得，payload 不允许声明用户身份。命令校验失败不得改变
牌、游标、响应或计数器。

## 响应窗口与优先级

弃牌后为每个有合法动作的座位生成私有候选集。候选集不作为公共事件广播。
没有候选动作的座位由引擎立即跳过；全部座位均无候选动作时直接进入下一家
摸牌。只有持有候选动作的玩家需要选择动作或 `Pass`。服务端超时只负责为
这些玩家代交 `Pass`；领域状态机不读取时钟。

所有需要响应的座位提交后一次解析：

1. 荣和；
2. 碰或明杠；
3. 吃。

同级碰/明杠按从放铳者下家开始的座位距离决定。吃只允许弃牌者的下一家。
荣和按 `ron_resolution` 选择头跳或多家和牌。公开规则的优先级依据
[日本プロ麻雀協会 競技規定](https://npm2001.com/about/regulations/)：
和牌优先于碰、杠，碰、杠优先于吃。

最后一张弃牌不得吃、碰、杠。加杠在抢杠响应结束前不修改原明刻；有人荣和
则杠不成立，也不翻新杠宝。暗杠抢杠资格由 `HandJudge` 判定，以便 M4 支持
国士无双等规则差异。

## 立直、振听和一发

- 立直请求与弃牌一起提交；
- 门清、点数、听牌及特殊牌型条件全部满足后标为“待成立”；
- 立直宣言牌无人荣和时才扣 1000 点并增加供托；
- 宣言牌被吃碰杠但无人荣和时，立直仍成立；
- 已立直者通常只能摸切，暗杠例外由 `HandJudge` 判定；
- 放弃可荣和牌产生同巡振听，自己下次摸牌时解除；
- 立直后放弃荣和升级为本局持续的立直振听；
- 任意吃碰杠取消所有人的一发资格；
- 立直者完成下一次未和牌摸打后失去一发资格。

自身牌河造成的永久振听需要知道完整等待牌集合，由 M4 的 `HandJudge`
判断；M3 保存牌河并先执行状态型振听限制。

## 流局

途中流局只在对应配置开启时触发：

- `nine_terminals`：玩家未鸣牌的首次摸牌阶段，至少九种不同幺九牌；
- `four_winds`：四麻四家第一打相同风牌，期间无人鸣牌；
- `four_kans`：第四个杠由至少两家共同完成；
- `four_riichi`：四麻四家立直均成立。

荣和优先于由同一弃牌触发的途中流局。四杠全由同一家完成时不触发四杠
散了，但全局不能声明第五个杠。

普通牌山耗尽且最后弃牌无人荣和时产生荒牌流局。各家听牌结论由
`HandJudge` 给出；点数收支、连庄和整场推进交给 M4。

## 领域事件

首批内部事件：

```text
HandStarted
InitialHandDealt
TileDrawn
TileDiscarded
ReactionSubmitted
MeldDeclared
KanCompleted
DoraIndicatorRevealed
RiichiEstablished
IppatsuCancelled
TsumoDeclared
RonDeclared
AbortiveDrawDeclared
ExhaustiveDrawDeclared
```

事件包含重放所需事实，但广播前必须投影：

- 本人可见自己的配牌和摸牌；
- 对手及观战者只能看见张数变化；
- 完整牌山、隐藏手牌和候选动作只进入加密 secret payload；
- 所有观察者共享事件序号和公共事实名称。

每个已接受命令产生一组有序事件。局结束事件包含结束原因和相关座位，不
包含 M4 尚未计算的分数。

## 恢复与不变量

M3 提供 `RiichiHandCheckpoint` 作为领域恢复信封，记录 schema、完整生效
规则、全部聚合状态和最新事件序号。创建与载入都执行不变量审计，调试输出
不暴露隐藏手牌和牌山。M7 的持久化适配器再把该领域状态映射为独立版本的
`json+zstd` 加密格式；不得直接保存 Rust 内存布局。

载入时至少校验：

- 每张物理牌只出现于一个当前区域；被鸣弃牌仅保留指向副露的历史引用；
- 玩家数、座位和规则集一致；
- 手牌张数与副露、阶段相符；
- 响应只能来自候选座位且每家至多一次；
- 杠、岭上摸和宝牌指示牌数量一致；
- `Ended` 后不存在待响应或当前行动者。

事件追加、单局记录和快照仍按
[存储设计](persistence.md)在同一事务写入。

## 性能约束

- 热路径用 `TileId` 和固定 34 牌种计数，不解析字符串；
- 玩家集合固定为三或四家，不使用哈希表查座位；
- 候选组合数量有严格上界；
- 合法命令直接推进状态，不为保证原子性复制完整牌山；
- 网络等待不占用领域锁，由每桌单写任务串行提交最终命令。
